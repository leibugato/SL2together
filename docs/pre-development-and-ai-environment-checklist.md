# 微信小程序项目前期准备与 AI 开发环境清单

## 0. 文档目的

文档用于回答三个问题：

1. 在正式开发前，用户需要完成哪些只能由管理员手工完成的工作。
2. 如何把本地仓库整理成适合 AI 持续开发和修改的环境。
3. 在什么条件下，AI 才可以稳定完成小程序、云函数和 AI 评估功能。

关联文档：

- `docs/wechat-mod-design-platform-design.md`
- `docs/technical-architecture-and-development-guide.md`

---

## 1. AI 能做什么和不能做什么

### 1.1 AI 可以直接完成

在代码和权限准备完成后，AI 可以：

1. 创建和修改微信小程序 TypeScript 页面。
2. 创建云函数、数据库访问层和类型定义。
3. 编写表单、历史记录、评估结果和管理员页面。
4. 编写 AI Provider 适配层和结构化输出校验。
5. 编写测试、Mock 数据和项目脚本。
6. 执行 lint、类型检查和单元测试。
7. 生成 README、接口协议、数据库迁移说明和发布检查清单。
8. 在本地 Git 仓库中创建分支和提交。

### 1.2 AI 不能代替你完成

以下步骤涉及账号、真实身份、微信扫码、平台确认或私密凭据，通常必须由你完成：

1. 注册微信小程序账号并完成主体认证。
2. 获取正式小程序 AppID。
3. 用管理员微信登录微信开发者工具。
4. 开通微信云开发环境。
5. 创建 `dev` 和 `prod` 云环境。
6. 配置云环境变量和 AI API Key。
7. 确认云开发套餐、额度和账单。
8. 在小程序后台配置服务类目、隐私保护指引和合法域名。
9. 提供或确认管理员微信号及其 `OPENID`。
10. 决定使用哪个 AI 服务商和预算上限。
11. 在微信开发者工具中扫码预览、真机调试和上传审核版本。

AI 可以告诉你怎么操作，也可以准备对应的代码和配置，但不能替你完成实名、授权、扫码和平台审核。

## 2. 开始前的最小准备条件

如果目标是让 AI 进入正式编码阶段，至少需要具备：

| 条件 | 必需时间 |
| --- | --- |
| 微信小程序 AppID | 项目初始化前 |
| 微信开发者工具已登录 | 项目初始化前 |
| `dev` 云开发环境 | 云函数开发前 |
| 云函数和云数据库权限 | 云函数开发前 |
| 当前 Git 仓库 | 已完成 |
| Node.js LTS 和 npm | 项目脚手架前 |
| AI 服务商和 API Key | 接入真实模型前 |
| 管理员身份方案 | 开发管理页前 |

可以分阶段准备。用户登录、草稿、提交和历史记录不需要 AI Key，因此可以先行开发。

## 3. 第一阶段：账号与小程序平台准备

### 3.1 注册并认证微信小程序

在微信公众平台完成：

1. 注册小程序账号。
2. 选择主体类型，个人或企业。
3. 完成主体认证要求。
4. 设置小程序名称、头像、简介和服务类目。
5. 获取小程序 AppID。
6. 添加开发者和管理员微信号。

需要特别确认：

1. 如果未来允许公开浏览用户提交，需要按 UGC 内容平台准备审核和内容安全能力。
2. 个人主体可能对部分社交、内容和管理能力有限制。
3. 服务类目应与“工具、社区、内容创作或效率”等实际功能一致。
4. 小程序名称和简介不要暗示与《杀戮尖塔 2》官方存在隶属关系。

### 3.2 确认管理员与开发者

至少准备：

1. 一个超级管理员微信。
2. 一个用于开发的普通开发者微信。
3. 如果多人开发，明确谁拥有云环境删除和账单权限。

建议：

1. 超级管理员只用于账号和权限管理。
2. 日常开发使用独立开发者微信号。
3. 不共享管理员微信扫码登录。

### 3.3 配置隐私与合规材料

提前准备：

1. 隐私保护指引。
2. 用户数据收集说明。
3. AI 第三方处理说明。
4. 用户删除数据和注销入口。
5. 内容安全与违规处置规则。
6. 美术和音频资源版权声明。

这些材料可以先做初版，正式提交审核前再完善。

## 4. 第二阶段：本地开发环境

### 4.1 安装必要软件

需要安装：

1. Git。
2. Node.js 当前 LTS 版本。
3. npm。
4. 微信开发者工具稳定版。
5. Visual Studio Code。

不需要：

1. Visual Studio 2022。

### 4.3 VSCode 建议配置

推荐：

1. 安装 ESLint、Prettier、GitLens、Error Lens。
2. 打开当前仓库 `C:\Users\akaset\Desktop\sl2_xcx`。
3. 将微信开发者工具与本仓库同时打开。
4. 使用 VSCode 编辑代码，使用微信开发者工具预览和部署。

## 5. 第三阶段：微信云开发准备

### 5.1 创建云环境

使用微信开发者工具或 CloudBase 控制台创建：

| 环境 | 用途 |
| --- | --- |
| `sts2-mod-dev` | 开发和测试 |
| `sts2-mod-prod` | 正式用户和生产数据 |

不要先在 `prod` 环境做表结构实验。

### 5.2 开通能力

确认以下能力可用：

1. 云函数。
2. 云数据库。
3. 云存储。
4. 云函数日志。
5. 定时触发器。
6. 环境变量或密钥配置。
7. 数据导入、导出和备份能力。

### 5.3 配置环境变量

开发环境先可以只配置：

```text
APP_ENV=dev
AI_PROVIDER=mock
AI_MODEL=mock-v1
MAX_DAILY_EVALUATIONS=20
```

接入真实模型时再配置：

```text
AI_BASE_URL=
AI_API_KEY=
AI_MODEL=
AI_TIMEOUT_MS=30000
```

安全要求：

1. `AI_API_KEY` 只存在云函数环境变量中。
2. 不提交到 Git。
3. 不发送到小程序客户端。
4. 开发和生产使用不同 Key。
5. 设置消费告警和每日预算。

### 5.4 云开发需要确认的信息

最终需要向项目提供：

1. 小程序 AppID。
2. `dev` 环境 ID。
3. `prod` 环境 ID。
4. 管理员微信号对应的 `OPENID`。
5. AI 服务商、Base URL、模型名和 Key。
6. 每日最大评估次数。
7. 是否允许用户上传图片和音频。

敏感内容只填写到云函数环境变量或本地私密配置中，不要直接贴在公开聊天记录里。

### 6.1 先用模板验证

建议先在临时目录创建一个“云开发 QuickStart”项目，完成一次：

1. 小程序登录。
2. 云函数调用。
3. 数据库写入。
4. 数据库读取。
5. 云函数日志查看。

## 7. 第五阶段：为 AI 准备仓库上下文

### 7.1 必须存在的项目文档

仓库中应至少保留：

1. `docs/wechat-mod-design-platform-design.md`
2. `docs/technical-architecture-and-development-guide.md`
3. `docs/pre-development-and-ai-environment-checklist.md`
4. `README.md`
5. `AGENTS.md`

### 7.2 `README.md` 应包含

1. 项目一句话说明。
2. 本地启动步骤。
3. 使用的 Node.js 版本。
4. 微信开发者工具配置方式。
5. 云环境 ID 的配置位置。
6. 测试、lint 和构建命令。
7. 云函数部署方式。
8. 数据库集合说明入口。
9. 不允许提交的敏感文件。

### 7.3 `AGENTS.md` 应包含

`AGENTS.md` 是给 AI 编码代理使用的项目级约束，建议写明：

1. 项目目标和技术栈。
2. 必读设计文档和技术文档。
3. `miniprogram/` 与 `cloudfunctions/` 的边界。
4. 禁止在客户端保存 AI Key。
5. 禁止客户端直接写核心业务集合。
6. 十种内容类型和状态枚举不得随意修改。
7. 数据库字段修改必须提供迁移说明。
8. AI 输出必须经过 Schema 校验。
9. 修改后必须执行的检查命令。
10. 新功能必须包含加载、空、失败和无权限状态。

### 7.4 需要建立的配置文件

| 文件 | 用途 |
| --- | --- |
| `package.json` | 依赖、脚本和 Node 版本 |
| `tsconfig.json` | TypeScript 严格模式 |
| `.gitignore` | 排除密钥、构建产物和本地配置 |
| `.env.example` | 不包含真实 Key 的变量示例 |
| `eslint.config.*` | 代码规范 |
| `prettier.config.*` | 格式化规则 |
| `vitest.config.*` | 单元测试 |
| `project.config.json` | 微信项目路径和 AppID |
| `sitemap.json` | 小程序页面索引配置 |

### 7.5 需要定义的共享契约

在编码前固定：

1. 十种内容类型。
2. 提交状态。
3. 评估任务状态。
4. 四档难度。
5. 云函数响应结构。
6. 错误码。
7. 数据库字段名。
8. AI 评估 JSON Schema。

这些内容应集中维护，不能在多个页面复制不同版本。

### 7.6 需要准备的 Mock 数据

至少准备：

1. 每种内容类型各一条样例提交。
2. 一份简单、困难、极难评估结果。
3. 一份 AI 超时任务。
4. 一份非法模型输出。
5. 一份管理员审计记录。

Mock 数据可以让 AI 在未接入真实模型时完成页面和任务流。

## 8. 第六阶段：安全与权限准备

### 8.1 Git 安全

必须忽略：

```text
node_modules/
.env
.env.*
!.env.example
.DS_Store
dist/
build/
miniprogram_npm/
cloudfunctions/**/node_modules/
private/
*.local
```

如果 AI Key 曾进入 Git 历史，必须立即吊销并更换 Key，不能只删除文件。

### 8.2 云函数安全

1. 所有写操作都通过云函数。
2. 从上下文读取 `OPENID`。
3. 不信任客户端传入的 `_openid`。
4. 管理员操作重新查询 `admins` 集合。
5. 日志不输出完整设计正文和 Key。
6. 敏感操作写入审计日志。

### 8.3 数据库安全

1. 核心集合默认仅云函数读写。
2. 用户不能跨用户查询。
3. 删除采用软删除。
4. 评估结果不可覆盖，按版本追加。
5. 建立分页和索引。

### 8.4 内容安全

1. 提交文本经过内容安全检查。
2. 外部资源链接不自动下载。
3. 语音和图片上传先做类型、大小和格式限制。
4. 违规内容进入人工处理或隐藏状态。

## 9. 第七阶段：建立 AI 可以执行的开发闭环

### 9.1 固定检查命令

项目初始化后，`package.json` 应提供：

```json
{
  "scripts": {
    "typecheck": "tsc --noEmit",
    "lint": "eslint .",
    "test": "vitest run",
    "test:watch": "vitest",
    "format": "prettier --write ."
  }
}
```

具体命令可以根据最终依赖调整，但必须保持统一入口。

### 9.2 给 AI 的任务粒度

不要让 AI 一次完成整个平台。推荐按垂直切片推进：

1. 项目脚手架。
2. 用户登录。
3. 新建卡牌草稿。
4. 提交列表。
5. 十种类型的动态表单。
6. AI Mock 评估。
7. 真实模型接入。
8. 评估历史和过期状态。
9. 管理员只读页面。
10. 管理员审核和重试。

每个切片都必须可以独立验证。

### 9.3 每次交给 AI 的信息

应包含：

1. 本次要实现的功能。
2. 对应设计文档章节。
3. 涉及的数据集合和字段。
4. 预期入口和结果。
5. 不应修改的内容。
6. 验收标准。
7. 可执行的测试命令。

不要只说“帮我做一个 AI 小程序”，这会迫使 AI 猜测大量产品和技术细节。

### 9.4 AI 修改后的验证

每次修改后：

1. 执行 `npm run typecheck`。
2. 执行 `npm run lint`。
3. 执行 `npm test`。
4. 在微信开发者工具中编译。
5. 使用测试云环境调用云函数。
6. 检查云函数日志。
7. 真机查看关键页面。

## 12. 最终需要提供给 AI 的环境信息

可以安全提供给 AI：

1. 小程序 AppID。
2. 开发环境 ID。
3. 目录结构。
4. 云函数名称。
5. 数据库集合和字段。
6. AI 模型名和非敏感 Base URL。
7. 测试账号的使用方式，不包含密码。
8. 错误日志和脱敏请求 ID。

不要提供给 AI 或提交到仓库：

1. AI API Key。
2. 微信登录敏感凭据。
3. 云开发主账号密钥。
4. 生产数据库导出。
5. 用户真实隐私数据。
6. 支付、身份证或手机号信息。

AI 需要的密钥应由你配置到云函数环境变量，AI 只编写读取 `process.env.AI_API_KEY` 的代码。
